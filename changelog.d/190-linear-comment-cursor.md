Fixed
- An incremental `tga linear sync --comments` no longer misses new and edited comments. It re-read an issue's comments only when the issue's `updatedAt` moved, and Linear does not reliably move it on a comment create or edit. The pass now reads each team's comments through Linear's `comments` query, filtered by the comment's own `updatedAt` after a per-team cursor minus a 10-minute overlap (250 per request, archived included), and upserts them by comment id. The cursor (`linear_comment_cursor`, migration v37, additive) is the newest comment `updatedAt` stored, never later than the walk's start, and moves only after the whole walk and its writes commit; a failed or malformed page fails the run non-zero with nothing written. The first run for a team reads all its comments the same way. A comment on an issue not yet in `linear_issues` is stored and counted in the summary line; one on no issue is counted and skipped. The incremental walk cannot see deleted comments: `--backfill --comments` keeps the per-issue walk, which removes them (#190).
