Fixed
- `collect` retries a repository's pre-walk `git fetch` inside the same run when it fails with a transient connect error (timeout, refused, reset; git2 class Net, Http, Ssh or Os). Defaults: 3 attempts, backoff from 2 s doubling to a 30 s cap plus up to 25% jitter; new optional repository keys `fetch_retries` and `fetch_retry_base_secs`. After 10 consecutive repositories exhaust their retries, the run stops retrying. Auth, credential, certificate and not-found errors are not retried. A repository that still fails keeps the stale-data refusal unless `--allow-stale` is given, and the fetch summary reports "N retried" (#262)
