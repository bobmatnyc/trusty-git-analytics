Added
- A bucket map maps each fine category to a bucket, so every classification has a primary (bucket) and a secondary (fine category within it). The consumer owns the map: `classification.buckets` in the main config wins, then a top-level `buckets:` map in the rules file (a later rules file's map replaces an earlier one), then tga's built-in fallback: Maintenance (`bug_fix`, `devops`, `security`, `qa`, `upkeep`), Value Creation (`new_feature`, `integration`, `content_design`), Foundational Investment (`platform_infrastructure`, `data_science`) and Internal Tooling (`internal_tooling`). A map that names a category the config does not know (other than `content_design`), repeats a category, or names a no-answer label is an error, wherever it is written. Nothing is stored and no migration runs (#111).
- `tga eval score` reports stratum-weighted primary accuracy over every scored row and secondary accuracy over rows labelled in a bucket with more than one category, next to the fine figure, plus unweighted counts with Wilson intervals and per-bucket rows, in `report.json` (`buckets`), `report.md` and the console. `tga::eval::run_score_with_buckets` scores against a given map (#111).
- `tga classify` prints a derived "By bucket" breakdown of the per-category counts, naming the map's source (#111).
- `tga eval score --rules` and `tga eval repredict --rules` name the rules file for one run in place of `classification.rules_file`, as `tga rules --rules` does (#111).
- `tga rules list --format json` prints `bucket_map`: the bucket map in effect, in map order, and its `source` (`config`, `rules_file` or `fallback`). `ClassificationPipeline::bucket_map_with_source` and `effective_bucket_map` return the same, and `BucketSource` names the level (#111).
- With `llm.source: jev`, the one category question per commit offers the rules' categories and, when the consumer supplies the bucket map, every fine category in it. The built-in fallback adds none (#111).
