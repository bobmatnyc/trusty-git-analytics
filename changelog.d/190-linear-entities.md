Added
- `tga linear sync --entities` also syncs the Linear workspace's teams, users, labels, projects, project milestones and cycles, archived ones included, into six new tables keyed by Linear's id, each with the GraphQL node in `raw_json` (migration v34, additive). Projects keep state, status, start and target dates, completed/canceled times, lead and team ids; cycles keep team, number, dates and the latest scope and completed counts, and a cycle with zero scope is flagged `is_empty` (#190).
- Each entity set is fetched in full, then its rows and its `linear_entity_sync_state` row commit in one transaction. A failed page, or a page whose `pageInfo` does not say whether more follow, writes nothing for that set and does not move its state; the summary line reports per-entity counts (#190).
- A stored entity row that a complete fetch no longer returns (purged, deleted, or on a team the key lost) gets `removed_at` set in the same transaction and is kept for name lookups; it is cleared when the row returns. The summary line reports the rows newly marked removed per set (#190).
- Library: `collect::linear::entities` (`EntityKind`, `LinearClient::fetch_entity_nodes`, `entities::store::commit_entity_sync`, which returns `EntityCommit`, and `get_entity_sync_state`) and three `CollectError` variants, `LinearEntityApi`, `LinearNestedConnectionTruncated` and `LinearPageInfoInvalid` (#190).
