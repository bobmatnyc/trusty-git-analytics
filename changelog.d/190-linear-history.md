Added
- `tga linear sync --history` stores each due Linear issue's workflow-state changes in `fact_linear_transitions` (from/to state and type, actor, time), the counterpart of JIRA's `fact_ticket_transitions`; `--comments` stores comment metadata in `fact_linear_comment_detail` (author, parent, times, body length; the body is never stored). Migration v36, additive (#190).
- An issue is read again only when its `updated_at` differs from the one its activity was last read at (`linear_issue_activity_state`); `--backfill` re-reads every issue of the team. Each issue's connection is walked in full with no cap, and its rows and marker commit together. A failed read stops the run with a non-zero exit naming the issue, and the issue stays due for the next run even though the issue cursor moved. `--dry-run` reports the due count and sends no per-issue request (#190).
- Library: `collect::linear::activity` (`ActivityKind`, `ActivityTarget`, `LinearClient::fetch_issue_activity`, `activity::store::activity_candidates`, `activity::store::commit_issue_activity`) and the `CollectError::LinearActivityApi` variant (#190).
