Added
- `tga report` and `tga analyze` append the Linear delivery section (the block `tga linear stats` prints) to `report.md` when the new `linear.stats.report: true` is set and the database holds synced Linear issues. The figures are measured as of the report's `Generated` time with the `linear.stats` bounds. Under `--author` the section is replaced by one line saying it is left out because it covers the whole workspace. It is left out when Markdown is not among the formats or no Linear issue is synced; with the switch off (the default) `report.md` is unchanged. A figure that cannot be computed fails the report with an error starting `Linear delivery section:`, and no report file is written. The report reads the Linear tables and never writes them (#190).
- `tga collect` and `tga analyze` run the bulk Linear sync with entities (the work of `tga linear sync --entities`) when the new `linear.sync_on_collect: true` is set: each `linear.team_keys` entry, or every team the key can see when the list is empty. Off (the default), collect makes no bulk Linear request. A Linear HTTP 404 is one counted warning and the run exits 0; a 401, 403, 5xx after retries or any other sync failure is a stage failure, so collect exits non-zero after its remaining stages (#146 contract) (#190).
- `core::config::LinearStatsConfig` gains `report` and `core::config::LinearConfig` gains `sync_on_collect` (both `#[non_exhaustive]`, default `false`); `commands::linear::collect_sync::sync_on_collect` (#190).
